# Формат файла хранилища `.lusakey`

Реализация: `libs/core/include/lusakey/core/vault/vault_file.h`, `libs/core/src/vault/vault_file.cpp`.

Один файл на хранилище. Все многобайтовые целые — little-endian.

| Смещение | Размер | Поле | Комментарий |
|---|---|---|---|
| 0 | 8 | `magic` | ASCII `"LUSAKEY\0"` |
| 8 | 2 | `version` | сейчас `1` |
| 10 | 1 | `kdfAlgId` | `1` = Argon2id |
| 11 | 1 | `aeadAlgId` | `1` = XChaCha20-Poly1305-IETF |
| 12 | 4 | `memoryKiB` | параметр Argon2id (память, КиБ) |
| 16 | 4 | `iterations` | параметр Argon2id (итерации) |
| 20 | 4 | `parallelism` | зарезервировано; libsodium всегда использует 1 линию |
| 24 | 16 | `salt` | соль Argon2id (`crypto_pwhash_argon2id_SALTBYTES`) |
| 40 | 24 | `nonce` | nonce AEAD (`crypto_aead_xchacha20poly1305_ietf_NPUBBYTES`) |
| 64 | 4 | `ciphertextLen` | длина шифротекста ниже, включая 16-байтный тег |
| 68 | `ciphertextLen` | `ciphertext` | `AEAD_encrypt(payload) = ciphertext \|\| tag(16)` |
| 68+N | 32 | `checksum` | BLAKE2b-256 от байт `[0, 68+N)` |

Итого заголовок (байты `[0, 68)`) — единственная открытая часть файла. Он же целиком передаётся как **AAD** в `crypto_aead_xchacha20poly1305_ietf_encrypt/decrypt`, поэтому подмена любого поля заголовка (версии, параметров KDF, соли, nonce, длины) детектируется при расшифровке через несовпадение тега, а не только по чек-сумме.

`checksum` — не граница безопасности (это делает тег AEAD), а дешёвый способ отличить «файл повреждён/обрезан» от «неверный пароль» ещё до попытки расшифровки: `readRaw()` проверяет чек-сумму сразу после чтения и бросает `ChecksumMismatch`, не трогая крипто-примитивы.

`payload` (расшифрованное тело) — версионируемая бинарная структура: метаданные хранилища + список записей (заголовок/логин/пароль/URL/заметки/теги/папка/TOTP-секрет+алгоритм+цифры+период/временные метки). Никакая структура (даже количество записей) не видна в зашифрованном файле — тело представляет собой один непрозрачный блоб.

## Экспорт/импорт

«Экспорт» — копия файла `.lusakey` целиком (он уже полностью зашифрован и самодостаточен). «Импорт» — открытие стороннего `.lusakey` файла его собственным паролем через `openAndDecrypt`, дальше — слияние или замена текущего хранилища на уровне `VaultService` (M2).

## Параметры Argon2id

`KdfParams::fast()` / `balanced()` (по умолчанию) / `strong()` — см. `crypto/kdf.h`. Параметры, использованные при создании хранилища, сохраняются в заголовке и используются при каждой последующей разблокировке — смена профиля требует явного «re-key» (полной пересборки файла с новой солью/параметрами).

## Сохранение = полное перешифрование

Хранилище не дописывается — каждое сохранение (`writeNew`) генерирует новую случайную соль и nonce и переписывает файл целиком (временный файл + атомарный rename). Это специально исключает любое управление счётчиком nonce между сохранениями: 24-байтный nonce XChaCha20 безопасно генерировать случайно при каждой записи.
